# Reproduction: depset

This patch backports upstream #26720, a change to how capture-checking keeps the
dependencies of capture-set variables. It changes performance, not behaviour, so
there is no wrong output to reproduce: the [feature doc](../depset.md)
describes the measured case (Soundness's `exegesis.core`) and the profiling that
shows it.

What is checked here, by `test.sh` (run by `bin/proscala-test`):

- the backported structure is in the compiler: its jar holds
  `dotty/tools/dotc/util/MutableIdentitySet.class`, which stock 3.9.0 lacks;
- a dependency-heavy capture-checked method, generated by `gen.sh` with 3,000
  references to a capability-taking method (in blocks of 30 statements, to stay well within a 1 MB stack), still compiles.

Neither is a timing comparison: wall-clock thresholds would make CI flaky. To
see the difference itself, compile `Many.scala` (`bash gen.sh 20000`) with
`-Yprofile-enabled` on a patched and an unpatched compiler and compare the cc
phase's time and allocation.
